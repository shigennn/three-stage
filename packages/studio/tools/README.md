# 計測ツール

このドキュメントでは、シーンの表示と性能を同じ条件で確認するコマンド `three-stage shot`、`three-stage measure`、`three-stage soak` の引数と出力を説明する。\
性能の上限と、測定結果の読み方は [performance.md](../../../docs/performance.md) を参照。

## コマンドの一覧

| コマンド | スクリプト | 機能 |
|---|---|---|
| `three-stage shot` | `cdp.mjs` | スクリーンショットの撮影と、2D UI の文字の検査 |
| `three-stage measure` | `measure.mjs` | 1 フレームの描画内容とフレーム間隔の測定 |
| `three-stage soak` | `soak.mjs` | 長時間動作させたときの、メモリとオブジェクト数の検査 |

`chrome.mjs` は、ヘッドレス Chrome の起動と CDP の接続を行うモジュールである。\
`cdp.mjs` と `soak.mjs` が使用する。\
リポジトリから実行する場合は、`three-stage` の代わりに `node packages/studio/bin/three-stage.mjs` を実行する。

## 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows |
| Chrome | 既定のパスは `C:/Program Files/Google/Chrome/Application/chrome.exe` |
| Node.js | 22 以上。リポジトリから実行する場合のみ |
| エディタのサーバー | ウィンドウを開かずに起動したもの |

GPU で描画する場合は、Chrome の ANGLE を D3D11 で動作させる。\
Chrome が既定のパス以外にある場合は、環境変数 `CHROME_PATH` で指定する。\
リポジトリから実行する場合は、グローバルの `fetch` と `WebSocket` を使用するため、Node.js 22 以上が必要である。\
インストールしたアプリケーションの `three-stage` は、アプリケーションに含まれる Node.js で動作する。

### エディタのサーバー

各コマンドは、エディタのサーバーが配信するページを開く。\
事前に、次のコマンドでウィンドウを開かずにサーバーを起動しておく。

```powershell
three-stage <folder> --no-open --port 5180
```

以下の例の URL は、このサーバーのものである。\
相対パスの引数と出力先は、コマンドを実行したフォルダを基準とする。

### Chrome のプロファイル

Chrome のプロファイルは、OS の一時フォルダ内の `three-stage-tools\` の下に作成される。\
同じプロファイルで Chrome が既に動作していると、新しく起動した Chrome は既存の Chrome に処理を渡して終了する。\
そのため、同じプロファイルを使用するコマンドは同時に実行できない。

| コマンド | プロファイル |
|---|---|
| `shot` | 3 番目の引数で指定した名前のもの |
| `measure` | 描画方式（`gpu`、`swiftshader`）ごとに 1 つ |
| `soak` | 実行ごとに作成し、終了時に削除する |

`shot` を同時に 2 つ実行する場合は、3 番目の引数でプロファイル名を分ける。\
`measure` は、同じ描画方式では同時に実行できない。

## preview.html

`http://127.0.0.1:5180/preview.html` は、組み込み先と同じ描画のみを表示するページである。\
3 つのコマンドは、いずれもこのページを開いて使用する。

### クエリパラメーター

| パラメーター | 既定値 | 説明 |
|---|---|---|
| `scene` | `scenes/main.stage.json` | 開くシーンの、`content/` からのパス |
| `bundle` | なし | Publish したバンドルの `manifest.json` のパス |
| `start` | `12:00` | モックデータの開始時刻。`HH:MM` 形式 |
| `speed` | `60` | モックデータの時刻の進行速度。実時間 1 秒あたりに進む秒数 |
| `variant` | 最初のバリエーション | モックデータのバリエーションの ID |
| `limit` | 制限あり | `0` を指定すると、30fps の制限を解除する |
| `res` | `1080p` | 描画解像度。`1080p`、`720p`、`auto`（Dynamic Resolution）のいずれか |
| `quality` | `high` | Quality。`high` または `low` |
| `ui` | 表示する | `0` を指定すると、2D UI を表示しない |

`bundle` を指定すると、`content/` のシーンの代わりにバンドルを開く。\
Publish の出力は `bundle=/dist/bundle/manifest.json` で開ける。\
`speed=1440` を指定すると、1 日が 1 分で進む。\
`ui=0` は、3D のみの負荷を測定するときに使用する。

### `window.__stage`

ページの `window.__stage` から、次の値を読み取れる。

| 項目 | 説明 |
|---|---|
| `stats` | ランタイムの `FrameStats` |
| `events` | `EventStore` |
| `played` | 再生した Event の一覧 |

`stats.last` が現在の値である。\
時間は直近 120 フレームの中央値、数は直前のフレームの値である。\
`played` の各要素は、「名前 Key 発生元」の形式の文字列である。\
発生元は、データの変化による再生では `data`、コードからの呼び出しによる再生では `call` になる。

## three-stage shot

`cdp.mjs` を実行し、ヘッドレス Chrome で 1920×1080 のスクリーンショットを撮影する。\
手順に `check` を指定すると、`check.js` で 2D UI の文字の重なりとはみ出しを数える。

```powershell
three-stage shot steps.json out/shots
```

| 引数 | 既定値 | 説明 |
|---|---|---|
| 1 番目 | 必須 | 手順の JSON ファイル |
| 2 番目 | 必須 | 画像の出力先フォルダ。存在しない場合は作成する |
| 3 番目 | `prof` | Chrome のプロファイル名 |

### 手順ファイル

`steps.json` は手順の配列で、先頭から順に実行される。

```json
[
  { "name": "noon", "url": "http://127.0.0.1:5180/preview.html?start=12:00", "wait": 10000, "check": true },
  { "name": "evening", "url": "http://127.0.0.1:5180/preview.html?start=18:00", "wait": 10000, "check": true }
]
```

各手順は、次の項目を表の順に処理する。

| 項目 | 型 | 説明 |
|---|---|---|
| `url` | 文字列 | 開く URL。load イベントを最大 10 秒待つ |
| `js` | 文字列 | ページを開いた後に評価する式。視点の切り替えなどに使用する |
| `keys` | 配列 | `js` の後に送信するキー入力 |
| `mouse` | 配列 | `keys` の後に送信するマウス操作。ドラッグの確認に使用する |
| `wait` | 数値 | 撮影前の待機時間（ms） |
| `out` | 文字列 | 評価して、結果を出力する式 |
| `check` | 真偽値 | `true` の場合、`check.js` を評価して結果を出力する |
| `thumb` | 文字列 | 幅 800 px の縮小画像（JPEG）の出力先パス |
| `name` | 文字列 | 画像のファイル名（`<name>.jpg`）と、出力行の見出し |
| `shot` | 真偽値 | `false` の場合は撮影しない |

`name` を省略した手順は撮影しない。\
`js` で発生した例外は、出力の最後の `errors:` に含まれる。

`keys` の要素は、次の項目を持つ。

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `key` | 文字列 | なし | キーの値。例: `"s"` |
| `code` | 文字列 | なし | キーのコード。例: `"KeyS"` |
| `keyCode` | 数値 | なし | 仮想キーコード。例: `83` |
| `ctrl`、`shift`、`alt` | 真偽値 | `false` | 修飾キーを押した状態にするかどうか |
| `text` | 文字列 | なし | 入力する文字 |
| `wait` | 数値 | `50` | 送信後の待機時間（ms） |

`mouse` の要素は、次の項目を持つ。

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `type` | 文字列 | なし | `down`、`move`、`up` のいずれか |
| `x`、`y` | 数値 | なし | 座標 |
| `held` | 真偽値 | `false` | `move` で、ボタンを押したまま移動するかどうか |
| `ctrl` | 真偽値 | `false` | Ctrl キーを押した状態にするかどうか |
| `wait` | 数値 | `30` | 送信後の待機時間（ms） |

### 出力

`out` と `check` の結果を、1 件 1 行で `<name> <JSON>` の形式で出力する。\
最後に `errors:` を出力する。\
`errors:` には、console の error と warning、ページの例外、ブラウザのログの error、`js` の例外が含まれる。\
エラーがない場合は `errors: none` になる。

### 描画方式

既定では、SwiftShader（CPU によるソフトウェア描画）で描画する。\
SwiftShader は表示の確認用であり、速度の測定には使用できない。\
速度は `three-stage measure` で測定する。

SwiftShader では、1 フレームの描画に数百 ms、読み込みに数秒かかるため、`wait` を長めに指定する。\
ランタイムは、フレーム間隔が 250 ms を超えると、1 フレームを 1/30 秒として進める。\
そのため SwiftShader では、カメラや Clip の再生が実時間より大幅に遅く進む。\
再生が進んだ後の場面を撮影する場合は、環境変数 `CDP_GPU=1` を設定して GPU で描画する。

## check.js

`check.js` は、`check: true` の手順でページ内で評価されるスクリプトである。\
ランタイムは、2D UI のステージの要素に `id="stage"` を付与する。\
`check.js` は、この要素の内部を検査する。\
2D UI がないページでは、`"no stage"` を返す。\
2D UI を登録していないプロジェクトのページと、`ui=0` を指定したページが該当する。

座標は、ステージ座標に換算して返す。\
ステージ座標の高さは 1080 で、幅はシーンの Aspect Ratio で決まる（16:9 では 1920、21:9 では 2520）。\
画面の解像度や Aspect Ratio にかかわらず、ステージの表示上の幅から倍率を求めて換算する。

表示されている文字は、テキストノードごとに数える。\
`opacity` が 0.12 未満の祖先を持つ文字は、表示されていないものとして扱う。

| 項目 | 説明 | 最大件数 |
|---|---|---|
| `stage` | ステージ座標の大きさ。例: `1920x1080` | — |
| `texts` | 表示されている文字の数 | — |
| `overlaps` | 異なる要素の文字どうしが、縦横とも 2 px を超えて重なっている箇所 | 30 |
| `overflow` | 背景か罫線を持つ最も近い祖先の要素から、文字がはみ出している箇所 | 30 |
| `clipped` | `overflow: hidden` や `clip` で切り取られている文字 | 20 |
| `edge` | ステージの外にはみ出している文字 | 20 |
| `align` | 横に並んだ要素で、上端か下端が 1 px を超え 200 px 未満ずれている組 | 20 |

`overflow` の対象とする祖先は、幅 40 px 以上、高さ 20 px 以上の要素に限る。\
`align` は、背景か罫線を持つ幅 160 px 以上、高さ 80 px 以上の要素を対象とする。\
`align` で比較するのは、縦方向に半分以上重なっている組のみである。

## three-stage measure

`measure.mjs` を実行する。\
WebGL2 の呼び出しを数え、1 フレームの描画内容を出力する。

```powershell
three-stage measure "http://127.0.0.1:5180/preview.html?start=12:00&limit=0"
```

| 引数 | 既定値 | 説明 |
|---|---|---|
| 1 番目 | 必須 | 測定する URL、または場面ファイル（`.json` で終わるパス） |
| 2 番目 | `gpu` | 描画方式。`gpu` または `swiftshader` |

`gpu` は、D3D11 経由で GPU を使用する。\
どちらの描画方式でも、垂直同期と Chrome のフレームレート制限を解除して動作させる。\
1 フレームの上限と比較する場合は、`preview.html` に `limit=0` を付与し、ランタイムの 30fps の制限も解除する。

### 場面ファイル

`runs.json` は場面の配列で、先頭から順に測定される。

```json
[
  { "label": "noon", "url": "http://127.0.0.1:5180/preview.html?start=12:00&limit=0" },
  { "label": "noon 720p", "url": "http://127.0.0.1:5180/preview.html?start=12:00&limit=0&res=720p", "warm": 6000 }
]
```

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `label` | 文字列 | `url` の値 | 出力行の見出し |
| `url` | 文字列 | なし | 開く URL。load イベントを最大 15 秒待つ |
| `js` | 文字列 | なし | ページを開いた後に評価する式 |
| `warm` | 数値 | `8000` | 集計を開始する前の待機時間（ms） |
| `sample` | 数値 | `6000` | 集計する時間（ms） |

`url` を省略した場面では、前の場面のページをそのまま測定する。

### 出力

次の順に出力する。

1. `GPU: <レンダラー名>`
2. 場面ごとに、`<label> <JSON>` の 1 行
3. `shaders`
4. `lights`
5. `errors:`（ページの例外）

場面の JSON は、次の項目を持つ。\
集計の対象は、draw call が 1 回以上あったフレームのみである。

| 項目 | 説明 |
|---|---|
| `frames` | 集計したフレーム数 |
| `calls`、`callsMax` | 1 フレームの draw call 数の中央値と最大値 |
| `instanced` | インスタンス数が 2 以上の draw call 数の中央値 |
| `tris`、`trisMax` | 1 フレームで描画した三角形数の中央値と最大値 |
| `lines`、`points` | 1 フレームで描画した線の頂点数と点の数の中央値 |
| `cpuMs`、`cpuP95` | 描画を行った rAF コールバック内の JS の実行時間の中央値と 95 パーセンタイル |
| `frameMs`、`frameP95` | フレーム間隔の中央値と 95 パーセンタイル |
| `canvas` | ページ内の最初の canvas のサイズ |
| `programs` | ページを開いてからリンクしたシェーダープログラムの数 |
| `pass` | viewport のサイズごとの集計 |

1 フレームの上限と比較する値は、`frameMs` である。\
`tris` には、シャドウマップやリフレクションのためにシーンを複数回描画した分も含まれる。\
`pass` は viewport のサイズごとに、そのパスを含むフレーム数（`frames`）、draw call 数（`calls`）、三角形数（`tris`）を持つ。\
シャドウマップ（`2048x2048` など）、メインのパス（`1920x1080`）、Bloom の縮小したレンダーターゲットは、別々に集計される。

`shaders` は、three.js のマテリアルの種類（`SHADER_TYPE`）ごとの、コンパイルしたフラグメントシェーダーの数である。\
`lights` は、ライトの種類ごとの、シェーダーが扱うライト数の最大値である。\
キーは three.js の `NUM_DIR_LIGHTS`、`NUM_DIR_LIGHT_SHADOWS` などの名前で、値はシェーダー内のライトの uniform 配列の要素数から読み取る。\
`AmbientLight` と `LightProbe` は配列を持たないため、含まれない。

### 測定条件

- ウィンドウは 1920×1080、デバイスピクセル比は 1 に固定する。\
  720p の上限と比較する場合は、`res=720p` で描画解像度を下げて測定する。
- HTTP キャッシュは使用しない。
- 保持するフレームは、直近の 2000 フレームまでである。\
  フレームレートの高いページでは、`sample` の期間の一部のみが集計される。

## three-stage soak

`soak.mjs` を実行する。\
ページを長時間動作させて JS のヒープと WebGL のオブジェクト数を記録し、増加し続けていないかを判定する。

```powershell
three-stage soak "http://127.0.0.1:5180/preview.html?start=00:00&speed=1440&limit=0" --minutes 30
```

`speed=1440` を指定すると、モックデータの 1 日が 1 分で進む。\
`limit=0` を指定すると 30fps の制限が解除され、同じ時間内に描画するフレーム数が増える。

| 引数 | 既定値 | 説明 |
|---|---|---|
| URL | 必須 | 開くページ |
| `--minutes` | `30` | 動作させる時間（分） |
| `--every` | `30` | 記録の間隔（秒） |
| `--warmup` | `2` | 判定から除外する最初の時間（分） |
| `--js` | なし | ページを開いた後に評価する式 |
| `--out` | `out/soak-<日時>.csv` | 記録する CSV のパス |
| `--swiftshader` | 指定なし | GPU を使用せず、SwiftShader で描画する |

実時間で 24 時間動作させる場合は、`--minutes 1440` を指定する。\
`--warmup` は、読み込みとシェーダーの作成による増加を判定から除外するために使用する。\
ページの load イベントは、最大 20 秒待つ。\
バックグラウンドタブとしての処理の間引きは、無効にして動作させる。

### 記録

記録のたびに、CDP で GC を実行してから次の列を CSV に 1 行追記し、同じ内容を 1 行出力する。

| 列 | 説明 |
|---|---|
| `min` | 開始からの経過時間（分） |
| `heapMB` | GC 後の JS のヒープサイズ（MB） |
| `texture`、`buffer`、`framebuffer`、`renderbuffer`、`program`、`shader`、`query`、`vao` | WebGL2 のオブジェクトの、作成数から削除数を引いた数 |
| `dom` | DOM の要素数 |
| `fps` | 前回の記録以降の、1 秒あたりの描画回数 |
| `frameMs` | `window.__stage.stats` のフレーム間隔の中央値 |

WebGL2 のオブジェクト数は、ページ内のすべての WebGL2 コンテキストを対象に数える。\
`fps` は、draw call を 1 回以上実行した rAF コールバックの数から求める。\
描画しない rAF のループと、30fps の制限で描画を省略したコールバックは数えない。\
`frameMs` は、`preview.html` 以外のページでは空になる。

### 判定

`--warmup` 以降の記録を 3 等分して判定する。\
後ろの 3 分の 1 の最小値が、前の 3 分の 1 の最大値を超えた列を、不合格（`FAIL`）とする。\
判定の対象は、`heapMB` から `dom` までの列である。\
`heapMB` のみ、2 MB までの増加を変動として許容する。\
`--warmup` 以降の記録が 3 つ未満の場合は、`samples` を不合格とする。\
その場合は、`--minutes` を増やすか、`--every` を減らす。

終了時に、次の内容を出力する。

| 出力 | 説明 |
|---|---|
| `heap slope` | ヒープの傾き。1 時間あたりの値と、24 時間に換算した値。判定には使用しない |
| `PASS`、`FAIL` | 列ごとの判定 |
| `errors:` | ページの例外 |
| `log:` | 記録した CSV のパス |
| `result:` | 全体の判定。`PASS` または `FAIL` |

| 終了コード | 条件 |
|---|---|
| `0` | 合格 |
| `1` | 不合格 |
| `2` | URL が指定されていない |
